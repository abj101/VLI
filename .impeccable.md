# Impeccable — JARVIS (VLI)

Design context for UI work in this repository. Update this file when product direction changes.

**Implementation source of truth:** `jarvis/src/glassTokens.css` (semantic color + glass material). Theme-specific editor aliases live in `jarvis/src/EditorRoot.css`; HUD aliases in `jarvis/src/App.css`. Do not duplicate palette values in component CSS — consume tokens.

## Design Context

### Users

The app serves people who are **comfortable with their computers** and want a **clean, elegant, and enjoyable** way to run automations and drive basic system actions. It is **unapologetically nerdy**: power-user affordances are welcome as long as the surface stays legible. The core job is to **run predetermined, branching action sequences quickly**, triggered by **voice commands** (with hotkey and editor support as part of the same workflow).

### Brand Personality

**Classy, purposeful, focused.** The interface should feel considered and calm, not busy or apologetic. Every visual choice should earn its place; whimsy appears where it supports the task, not as decoration for its own sake.

### Aesthetic Direction

- **North star:** **Luxury quiet** with **selective expressiveness** — restrained default chrome, clear hierarchy, and memorable moments where state changes matter (for example listening, match, execution feedback on the HUD).
- **Color personality — warm ink family:** Light and dark share a **warm neutral ink** hue (~72–82 OKLCH). Light reads as **cream day** (off-white paper, soft shell); dark reads as **ink night** (lamp-lit graphite, never blue-washed). **Warm bronze** is the **only** saturated hue — muted lamp-brass accent reserved for focus, selection, and active controls.
- **Surfaces — frosted glass default:** Overlays and the **HUD** use **frosted glass** with **subtle transparency** (not heavy wash), restrained blur, and a soft edge highlight. Prioritize readability first: translucency only where text remains comfortably legible.
- **Reference language:** **Apple macOS** — continuity of shape, **purposeful glass** (material depth, blur, and layering where it aids comprehension), disciplined **typography**, and **careful color** (tinted neutrals with intentional accent use). This is inspiration for *craft*, not pixel-for-pixel imitation of Apple apps.
- **Anti-patterns:** Avoid a **Windows 11** decorative / “settings app” flavor; avoid **Cursor-like** saturated dev-tool palettes; avoid **generic shadcn** template layouts (same card grids, same purple accents, same component soup); avoid **cool gray or blue-washed** neutrals on either theme; avoid **pure black** (`oklch(0 0 0)`) or **pure white** surfaces.
- **Theme (current phase):** Ship **light and dark** as equal citizens with **identical geometry**; only color and material shift between themes.
- **Accessibility:** Meet **WCAG 2.1 AA** for contrast and interactive targets where applicable. Dark body text targets **≥ 7:1** on main surfaces where feasible.
- **Motion:** Keep motion **sparse and functional**; honor `prefers-reduced-motion` when motion is present.

### Design Principles

1. **Voice-first clarity** — Surfaces (HUD, editor, settings) make **state and outcome** obvious at a glance; transcription and command feedback stay the hero where relevant.
2. **Quiet luxury, loud moments** — Default UI stays **calm and spacious**; **expressive** treatment reserved for **meaningful transitions** (listen / match / execute / done), not global animation noise.
3. **Glass with intent** — HUD glass stays **subtle**: enough translucency to feel native, enough tint/contrast to keep text readable on varied wallpapers.
4. **Warm ink, not template gray** — Neutrals are **tinted** toward the shared ink hue family; warm bronze accent appears only where interaction demands it.
5. **Apple-adjacent craft, not cliché** — Favor **rounded continuity**, **typographic discipline**, and **stepped luminance** over flat slabs; still **distinctly JARVIS**, not a stock “Big Sur clone.”
6. **Anti-generic product UI** — Reject **Win11** ornament, **IDE neon**, and **template-dashboard** patterns; custom composition and spacing over repeated card-icon-title grids.
7. **AA non-negotiable** — Light and dark themes both ship with **contrast-safe** text, borders, and controls.

## Token Reference (June 2026)

Concrete values for HUD, editor, and settings. CSS variable names in `glassTokens.css` omit the `dark`/`light` prefix — light values live on `:root`; dark overrides live on `[data-theme="dark"]`.

### Accent (both themes)

| Token | Value | Use |
|-------|-------|-----|
| `--color-accent-hex` | `#8A6B42` (light) / `#C4A06A` (dark) | Toggles, focused controls, active radio, selection rings |
| `--color-accent-strong-hex` | `#6F5532` (light) / `#D4B27E` (dark) | Pressed / emphasized accent |
| `--color-accent` | `oklch(0.54 0.095 64)` (light) / `oklch(0.72 0.1 68)` (dark) | OKLCH accent for `color-mix` |

**Rule:** Accent is **never** a full-screen wash. Selection backgrounds use `--color-accent-soft-hex` (theme-specific, below).

### Light — cream day

**Personality:** Morning paper, warm shell — cream and off-white, not cool `#F3F4F6` gray.

| Role | Hex (approx.) | OKLCH (`glassTokens.css` `:root`) |
|------|---------------|-------------------------------------|
| App background | `#F5F0E8` | `oklch(0.962 0.014 82)` |
| Main surface | `#FDFAF5` | `oklch(0.988 0.01 82)` |
| Elevated surface | `#F7F2EA` | `oklch(0.975 0.012 80)` |
| Sidebar | `#EDE8DF` | `oklch(0.954 0.016 78)` |
| Divider | `#D8D0C4` | `oklch(0.87 0.016 78)` |
| Text primary | `#2A2620` | `oklch(0.28 0.018 72)` |
| Text secondary | `#6B6358` | `oklch(0.5 0.02 72)` |
| Accent soft (selection wash) | `#EAE1D0` | — |

**Relationship rules:**

- Main content surface **lighter** than app background.
- Sidebar / secondary pane **slightly darker** than main content.
- Text uses **warm ink**, never pure black.
- Borders stay low-contrast and warm-tinted; no stark black outlines.

### Dark — ink night

**Personality:** Evening room, lamp-lit graphite — warm off-black, legible stepped surfaces, **no blue wash** on neutrals.

| Role | Hex (approx.) | OKLCH (`[data-theme="dark"]`) |
|------|---------------|-------------------------------|
| App background | `#1A1816` | `oklch(0.2 0.009 72)` |
| Main surface | `#23211E` | `oklch(0.24 0.01 72)` |
| Elevated surface | `#2C2925` | `oklch(0.28 0.011 72)` |
| Sidebar | `#1F1D1A` | `oklch(0.22 0.009 72)` |
| Divider | `#4A4640` | `oklch(0.41 0.012 72)` |
| Text primary | `#EDEAE6` | `oklch(0.93 0.006 72)` |
| Text secondary | `#B8B2A8` | `oklch(0.77 0.011 72)` |
| Accent soft (selection wash) | `#3D3630` | — |
| Glass text subtle | — | `oklch(0.7 0.01 72)` |

**Relationship rules:**

- App background is **warm ink off-black** — never `oklch(0 0 0)`.
- All neutrals share hue **~72**; surfaces and text must not drift toward blue/slate.
- Primary surfaces **one step lighter** than background; elevated **one step lighter** than primary; sidebar **between** background and main.
- Text uses **warm off-white**, never pure white.
- Editor controls and borders in `EditorRoot.css` mix toward **opaque surfaces** (~72–90% surface opacity), not heavy `transparent` washes that collapse contrast.
- Muted / placeholder text uses `--color-text-secondary` or mixes toward **transparent**, not **black**.

### Cross-theme cohesion

- **Shared ink hue:** Light surfaces ~78–82, dark surfaces ~72; text ink ~72 in both themes.
- **Stable semantic ladder:** `bg-app` → `surface-main` → `surface-elevated` → `divider` → `text-primary` → `text-secondary`.
- **Same accent behavior** in both themes (focus / selection / active only).
- **No double-dark / double-flat layering** — parent and child surfaces must differ by at least one luminance step.
- **Legibility over wallpaper** — any blur or transparency must be validated against busy desktop content.

## Material & glass

Implemented via `glassTokens.css` utilities (`.glass-panel-0|1|2`) and HUD-specific rules in `App.css`.

### HUD

| Token | Light | Dark |
|-------|-------|------|
| `--material-hud-alpha` | `78%` | `88%` |
| `--material-hud-blur` | `18px` | `18px` |
| `--material-hud-saturate` | `1.08` | `1.08` |
| `--hud-window-bg` | `oklch(0.988 0.01 82)` | `oklch(0.2 0.009 72)` |

- `.hud-root` is a **single** glass surface (no stacked panel utilities).
- Ancestor chain (`html` → `body` → `#root` → `.hud-panel-fill`) must stay **transparent** so `backdrop-filter` blurs the desktop.
- Dark HUD uses a flat glass fill (no vertical wash gradient).

### Settings / editor panes

| Token | Light | Dark |
|-------|-------|------|
| `--material-settings-pane-alpha` | `90%` | `92%` |
| `--material-settings-group-alpha` | `90%` | `94%` |
| `--glass-1-fill` / `--glass-2-fill` | pane / group alpha | `90%` / `90%` |
| `--glass-0-fill` (dark only) | — | `88%` |

Editor semantic aliases (`--editor-control-bg`, `--editor-border`, etc.) are derived in `EditorRoot.css` from the semantic palette above — do not hardcode theme hues in components.

### Contrast targets

| Context | Minimum |
|---------|---------|
| Body text on any surface | **≥ 4.5:1** |
| Large text (≥ 18px regular or ≥ 14px bold) | **≥ 3:1** |
| Focus ring vs adjacent color | **≥ 3:1** |
| Dark mode body text (target) | **≥ 7:1** where feasible |

## Corner radius

Current implementation in `glassTokens.css` (editor/HUD shell):

| Token | Value | Use |
|-------|-------|-----|
| `--radius-window` / `--radius-outer` | `12px` | Frameless window shell, HUD outer curve |
| `--radius-large` | `14px` | Large panels |
| `--radius-medium` | `12px` | Medium panels |
| `--radius-control` | `10px` | Inputs, chips, tags |
| `--radius-chip-pill` | `999px` | Pills |

**Rule:** Nested surfaces step down by **2px** per layer where concentric rounding applies. `prefers-contrast: more` may zero out radius (see `EditorRoot.css` / `App.css`).

## What this supersedes

- Cool gray light neutrals (hue ~250) and blue-tinted dark neutrals (hue ~258).
- Pure-black dark backgrounds and collapsed transparent editor control layers.
- Prior “heavy diffusion / high-opacity milky glass” HUD direction — replaced by subtle transparency with strict readability constraints.
- Prior “light theme only” direction — dark mode is required and quality-equal.
- Cool blue `--color-accent-soft-hex: #DCEBFF` on light — replaced by warm cream `#EAE1D0`.
- macOS blue accent (`#0A84FF`, hue ~257) — replaced by warm bronze (`#8A6B42` / `#C4A06A`, hue ~64–68, chroma ~0.10).

## Engineering notes

- **HUD + editor** split: overlay for capture/feedback; **separate editor window** for command CRUD. Editor: **no emoji**; **geometric** icon language; **10px** control radius and **44px** row rhythm where applicable per `BrainStorm.md` unless a deliberate design pass updates those tokens coherently.
- **Stack:** Tauri 2, React, Framer Motion, Zustand — motion should remain **light** per direction above.
- **Windows:** Frameless WebView requires transparent host background (`#00000000` in tauri.conf) for glass to composite correctly; see `App.css` transparency chain comments.
